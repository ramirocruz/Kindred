# Kindred context index

Use this folder as the project memory for future work. Treat claims marked **Verified** as observed, **Implemented** as code/deployed but not necessarily end-to-end proven, and **Hypothesis** as a lead that must be checked before changing code. Do not turn a hypothesis into a product claim.

When completing a Kindred task, update the relevant document(s) in the same change. Add dates, evidence, and remaining uncertainty rather than implying success from a build alone.
